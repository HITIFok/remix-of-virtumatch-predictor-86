SECTION 8: THE PLAYOUT ENDPOINT — EARLY DATA SOURCE ANALYSIS
================================================================================

Known behavior (from task description):
  - URL: GET /8035/round/{N}/playout?parentEventCategoryId=8035
  - Returns 400 when data isn't available yet
  - Returns match data with goals/scores ~2-3 seconds before match start
  - homeTeam and awayTeam are always null — must match by match ID only
  - Returns 404 in our tests (likely timing issue — data not available)

Timing analysis:
  - Virtual matches are 3 minutes long, generated every 3 minutes
  - Playout data becomes available 2-3 seconds before the scheduled start
  - The round-level expectedStart in /matches shows the actual schedule
  - Polling playout every 1-2 seconds near the expectedStart should catch the data

NOTE: In the previous exploration, all playout endpoints returned 404, not 400.
This may indicate the URL pattern was wrong at the time, OR data simply wasn't 
available for those rounds. The task states the correct pattern, but the URL may 
have changed. Further live testing during an active round is needed.

SECTION 9: CONCLUSIONS & KEY FINDINGS
================================================================================

1. ONLY 3 WORKING ENDPOINTS EXIST:
   /matches, /ranking, /results — that's it. No other endpoints were found.

2. NO EARLY SCORE DATA IN /matches:
   The /matches endpoint contains ZERO score or result information. The match 
   objects only contain team names, odds, and betting market data. There are 
   no hidden fields, no encrypted scores, no predetermined results.

3. THE PLAYOUT ENDPOINT IS THE ONLY KNOWN EARLY DATA SOURCE:
   It returns results 2-3s before the match officially starts. This was 
   confirmed in the task description and existing project documentation.

4. NO STREAMING/WEBSOCKET:
   No real-time data delivery mechanism exists. Polling is required.

5. SCORE EXACT ODDS COULD BE USEFUL:
   The "Score exact" market in /matches lists odds for every possible scoreline
   (0-0 through 6-0 = 28 outcomes). The odds reflect the algorithm's internal 
   probability distribution but do NOT reveal the predetermined result.

6. ROUND expectedStart IS THE KEY TIMING SIGNAL:
   The /matches endpoint provides `rounds[].expectedStart` which is the actual
   UTC timestamp for when the round starts. This is critical for timing the 
   playout polling — start polling playout 10-15 seconds before expectedStart.

7. HEADERS REQUIRE CORRECT ORIGIN + APP-VERSION:
   The sportybet.com origin returns 403. The bet261.mg origin with app-version 
   header works. The API validates both the Origin and the App-Version.

SECTION 10: RECOMMENDED APPROACH FOR EARLY DATA EXTRACTION
================================================================================

Step 1: Call GET /8035/matches with working headers
Step 2: Parse the round's expectedStart timestamp
Step 3: ~10 seconds before expectedStart, begin polling:
        GET /8035/round/{N}/playout?parentEventCategoryId=8035
        every 500ms-1000ms
Step 4: When playout returns 200, extract match IDs and scores
Step 5: Match playout match IDs with /matches data for team names
Step 6: Results appear ~2-3 seconds before official match start
